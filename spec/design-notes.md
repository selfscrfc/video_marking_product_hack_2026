# Дизайн-система Industry: что берём, чего не хватает, что конфликтует

Разбор проекта **Industry** в Claude Design (`49ef16de-57d1-4d23-9cb8-d79c6a23fc6e`) под
редактор разметки. Цель разбора — не описать систему, а понять, что из неё можно взять
готовым, что придётся достроить и где её правила спорят с задачей.

Короткий вывод: как визуальный язык Industry задаче подходит — техническая, чертёжная,
плотная, без украшательства; ровно та интонация, что нужна инструменту разметчика. Как
набор компонентов она задачу **не покрывает**: в ней нет ни одного из элементов, из
которых редактор в основном и состоит.

---

## 1. Что такое Industry

Из `theme.json` и `readme.md`:

| Параметр | Значение |
|---|---|
| Подложка | `--color-bg` `#f2f2f3`, поверхность `#e9e9ea` |
| Текст | `--color-text` `#1d1f20` |
| Акцент | `#5980a6`, сталь. Схема **mono** — второго акцента нет |
| Шрифты | Barlow Condensed (заголовки) над Barlow (текст) |
| Плотность | 0.85 — компактнее обычного |
| Радиус | 4 px |
| Рамка | `blueprint`: квадратные углы, hairline-граница, регистрационные кресты по углам |
| Изображения | `duotone` — обесцвечивание и заливка акцентом |
| Иконки | Lucide, толщина штриха 1.5 |

Правила, которые система задаёт жёстко:

- один `styles.css` на все страницы; любой цвет, шрифт, отступ, радиус и тень берутся из
  переменных (`var(--color-*)`, `var(--space-*)`, …). Хардкод — нарушение;
- каждая рамочная сущность носит `.blueprint` плюс четыре `<i class="corner tl/tr/bl/br">`.
  Снимать кресты с рамочного элемента нельзя;
- карточки и фигуры — прозрачные линейные объекты без заливки. Единственный залитый
  объект — первичная кнопка;
- у каждой роли есть тональная рампа 100–900, построенная в OKLCH на общей шкале
  светлоты. Ad-hoc `color-mix()` не нужен, берётся шаг рампы;
- состояния встроены: hover и pressed из рампы, фокус — `2px solid var(--color-accent)` с
  `outline-offset: 2px`, disabled — 45 % непрозрачности. Переопределять их постранично
  нельзя.

Два шаблона в `templates/` — это лендинг вымышленного каталога крепежа Holdfast и
презентация. **Экранов нашего приложения в системе нет**, и брать оттуда нечего, кроме
интонации и приёмов вёрстки.

## 2. Что берём готовым

| Компонент системы | Куда идёт в приложении |
|---|---|
| `.nav` + `.nav-brand` | Шапка: название, ролик, действия |
| `.table` | Список шагов: №, начало, конец, действие, объект, уверенность |
| `.card` + `.blueprint` (`.card-kicker`, `.card-title`, `.card-body`, `.card-meta`) | Карточка шага и рамка вокруг ключевого кадра |
| `.seg` + `.seg-opt` | Переключатель профиля гранулярности: «контактные фазы» / «крупные шаги» |
| `.tag` (`.tag-accent`, `.tag-neutral`, `.tag-outline`) | Метки «правлено вручную», «проверить» |
| `.field` + `label`, `.input` | Правка действия, объекта, инструмента; поля времени |
| `.dialog` + `.dialog-backdrop` | Диалог экспорта, подтверждение удаления шага |
| `.btn`, `.btn-secondary`, `.btn-ghost`, `.btn-icon` | Действия панели и строки |
| `.btn-primary` | Экспорт |
| `.elev-sm/md/lg` | Всплывающие слои над таймлайном |

Про `.btn-primary` — наше практическое следствие, а не буква системы: раз первичная
кнопка объявлена единственным залитым объектом на доске, на экране редактора она должна
быть одна. Кандидат очевиден — «Экспорт», конец работы. Всё остальное (добавить шаг,
разрезать, слить, отменить) уходит в `.btn-secondary` и `.btn-ghost`.

## 3. Чего в системе нет

Ниже — компоненты, из которых редактор состоит по существу. В Industry нет ни одного.

| Нужно | Зачем | Как строить в грамматике системы |
|---|---|---|
| **Дорожка таймлайна** | Основной экран: сегменты во времени | Квадратные блоки в hairline-рамке встык; выделенный — залит акцентом (он же становится вторым залитым объектом на экране — это осознанное расширение правила, см. п. 5) |
| **Плеер со своей шкалой** | Нативные контролы `<video>` игнорируют тему | Шкала — линия 1 px `--color-divider`, головка — вертикальная черта акцента; кнопки — `.btn-icon` с Lucide 1.5 |
| **Ручки перетаскивания границ** | Главный жест: правка границы одним движением | Вертикальный штрих на стыке сегментов, при наведении — крест регистрации, как у рамок. Зона захвата шире рисунка (≥ 8 px), иначе в границу не попасть |
| **Полоса кадров** | Понять, где действие, не проигрывая ролик | Кадры встык, каждый в hairline-рамке; кресты только на краях полосы, иначе рябь |
| **Индикатор обработки по стадиям** | 7 стадий, до 2 минут | Не круговой спиннер, а список стадий с отметками — под чертёжную интонацию ложится, и честнее: внутри `infer` прогресс всё равно оценочный |
| **Дропзона** | Вход в приложение | Пунктирная hairline-рамка с крестами; лимиты подписью из `GET /config` |
| **Тосты и инлайн-ошибки** | Конфликт версий, отказ валидатора | Сообщение в рамке с крестами; цвета нет, вес несёт заголовок Condensed |
| **Пустое, загрузочное, ошибочное состояния** | Три экрана из четырёх до первой разметки | Те же рамки, текст `--color-text` 78 % |
| **Выделенная строка таблицы** | Строка = шаг, синхронизирована с таймлайном | См. п. 4 — в системе есть hover, но нет выбранного состояния |

Это и есть главный вывод разбора. Обещанное трёхкратное сокращение времени держится не на
качестве модели, а на скорости правки — то есть ровно на этих компонентах. Ни один из них
не собирается из готового.

## 4. Конфликты, требующие решения

### Дуотон на ключевом кадре

`readme.md` требует прогонять через `.duotone` **каждую** контентную фотографию: «every
content photograph goes through it», изображения десатурируются и заливаются акцентом.

Для маркетинговой картинки это верно. Для ключевого кадра — нет. Кадр здесь не
иллюстрация, а рабочий материал: разметчик по нему опознаёт объект и решает, правильно ли
модель назвала «кружку». Обесцвеченный и залитый сталью кадр мешает делать ровно ту
работу, ради которой продукт существует.

**Решение:** зафиксировать исключение — контентные медиа (видео, кадры, полоса кадров)
идут в истинном цвете. Рамка и регистрационные кресты остаются, дуотон снимается. Это
нужно записать в `readme.md` самой системы, иначе исключение будет выглядеть недосмотром
и однажды кто-то «починит» его обратно.

### Уверенность нельзя закодировать цветом

Схема mono, и система прямо запрещает декоративный цвет сверх стального акцента. Значит
привычного «красный — плохо, зелёный — хорошо» не будет.

**Решение:** уверенность кодируется шагом рампы и меткой `.tag`, а не оттенком. И раз
порог — не свойство картинки, а свойство данных, считать его должен сервер: в ответе API
рядом с `confidence: 0.41` приходит `needs_review: true`. Иначе каждый экран определит
порог по-своему и подсветка разъедется между таблицей и таймлайном.

Это единственное место, где дизайн-система напрямую диктует форму API.

### Акцент не годится для мелкого текста

Пара акцент/подложка выверена на 3:1 — этого хватает иконкам, крупному тексту и хрому
интерфейса, но не абзацу. Система предписывает для мелкого текста в акценте брать
`--color-accent-700`.

**Где это заденет:** подписи таймлайна и шкалы времени (13 px), номера шагов, счётчики в
шапке. Все они мелкие и все просятся в акцент. Берут `--color-accent-700`.

### Таблица: hover есть, выделения нет

У компонента `.table` строки реагируют на наведение. В лендинге это глушится
(`tr:hover { background: none }` — «печатный лист, не интерактивная сетка»).

В редакторе всё наоборот: строка — это шаг, она кликабельна, синхронизирована с таймлайном
и с плеером, и у неё есть **выбранное** состояние, которого в системе нет вовсе. Нужен
вариант строки (`aria-selected` / `.is-selected`) — новое состояние компонента, а не
переопределение постранично.

## 5. Что предлагается изменить в самой системе

Три правки в проекте Industry, все — дополнения, ни одна не ломает существующие страницы:

1. **Исключение для контентных медиа** в разделе про `.duotone`: видео и кадры — в
   истинном цвете, рамка и кресты сохраняются.
2. **Второй залитый объект — выделенный сегмент таймлайна.** Правило «единственный залитый
   объект — первичная кнопка» написано для страниц, а не для инструмента с временной
   шкалой: выделение сегмента обязано читаться с расстояния. Расширение надо записать явно
   и ограничить: залит ровно один сегмент — текущий.
3. **Выбранное состояние строки таблицы** — как вариант компонента, рядом с hover и
   focus-visible.

Правки в Claude Design в этой задаче не вносятся: это рекомендация, а не изменение.

## 6. Следствия для API

| Наблюдение в дизайне | Что из этого следует в контракте |
|---|---|
| Mono-палитра, цветом уверенность не покажешь | `needs_review: boolean` рядом с `confidence`, порог считает сервер |
| Счётчики в шапке («7 шагов, 2 на проверку») | `stats` в ответе разметки, а не подсчёт на клиенте по разным правилам |
| Полоса кадров и предпросмотр при замене кадра | `GET /videos/{id}/frame?ts=&w=` с кэшем на диске |
| Превью в карточке шага | `keyframe_url` прямо в сегменте, чтобы клиент не собирал путь строкой |
| Плеер с перемоткой | `GET /videos/{id}/content` с поддержкой `Range` |
| Индикатор по стадиям, а не спиннер | `stage`, `stage_index`, `stages[]`, `timings` в задаче |
| Дропзона подписывает лимиты | `GET /config` отдаёт лимиты, клиент их не хардкодит |
| Разрез и слияние — по одному жесту | отдельные `POST …/split` и `POST …/merge`, а не три правки границ |
| Сбой разбора надо показать, а не съесть | `GET /jobs/{id}/raw` и отдельный код `model_parse_failed` |

Таблица двусторонняя: если в интерфейсе появится элемент, которому здесь нет строки, —
контракт неполон; если в контракте появится метод, которому нечего показать, — он лишний.
