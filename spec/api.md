# API: разбор и примеры

Машиночитаемый контракт — [`openapi.yaml`](openapi.yaml). Здесь то, чего в нём нет:
порядок вызовов, почему решения приняты именно такие, и на что смотреть при отладке.

База: `http://localhost:8000/api/v1`. Аутентификации нет — роли пользователей и биллинг
кейс выносит из скоупа, и в спецификации это записано явно (`security: []`), а не оставлено
пропуском. Сервис рассчитан на доверенную сеть.

---

## Как устроен пайплайн, если смотреть со стороны API

Разметку считает **Marlin-2B на Modal одним проходом**: ролик на вход, перечисление
событий с таймкодами на выход. Отдельного этапа поиска границ нет.

У этого есть следствие, которое видно в контракте. Marlin не разделяет глагол и объект —
он возвращает строку целиком: `<0.0 - 3.5> берёт кружку`. Кейс требует действие и объект
раздельно, и целевая метрика («не менее 80 % действий **и объектов** определены верно»)
меряет обе колонки. Поэтому после Marlin идёт короткий текстовый проход через LLM,
вызываемую через OpenRouter,
который делит описание на `action` / `object` / `tool` и проставляет `confidence`. Видео
он не видит — только 6–10 коротких строк, одним запросом на весь ролик, чтобы модель
держала формулировки соседних шагов однообразными.

Отсюда две стадии в `GET /jobs/{id}`: `infer` (Marlin) и `structure` (Claude). Когда
разметка приходит с пустыми `object`, виновата вторая, а не первая — и это видно по
`timings` и по `GET /jobs/{id}/raw`.

## Сценарий целиком

### 1. Узнать лимиты

```bash
curl -s localhost:8000/api/v1/config
```

```json
{
  "min_duration_s": 5, "max_duration_s": 30, "min_height": 720,
  "accepted_mime": ["video/mp4", "video/quicktime"],
  "max_size_bytes": 209715200,
  "confidence_threshold": 0.6, "min_segment_s": 0.4,
  "profiles": [{"id": "contact_phase", "title": "Контактные фазы"}],
  "structure_models": ["anthropic/claude-haiku-4.5", "anthropic/claude-sonnet-5",
                       "anthropic/claude-opus-5"]
}
```

Фронт берёт лимиты отсюда и **не хардкодит их**. Иначе подпись в дропзоне («до 30 секунд,
от 720p») начнёт расходиться с тем, что реально проверяет сервер, и пользователь получит
отказ после загрузки вместо предупреждения до неё.

### 2. Загрузить ролик

```bash
curl -s -X POST localhost:8000/api/v1/videos -F file=@clip00.mp4
```

```json
{
  "video_id": "6f2b…", "filename": "clip00.mp4", "mime": "video/mp4",
  "duration_s": 30.0, "fps": 30.0, "width": 1280, "height": 720,
  "size_bytes": 8123456, "sha256": "9ab1…", "created_at": "2026-09-05T13:44:02Z"
}
```

Проверка синхронная, через `ffprobe`. Отказы приходят кодами `video_format_unsupported`,
`video_duration_out_of_range`, `video_resolution_too_low`, `video_too_large`.

Дедупликация по sha256: тот же файл вернёт `200` и уже существующую запись вместо
дубликата. Полезно на демо, где один и тот же ролик грузят по десять раз.

### 3. Запустить разметку

```bash
curl -s -X POST localhost:8000/api/v1/videos/6f2b…/jobs \
  -H 'content-type: application/json' \
  -d '{"profile": "contact_phase", "structure_model": "anthropic/claude-haiku-4.5"}'
```

`202`, в `Location` — адрес задачи. Идемпотентно по паре (ролик, хэш параметров): второй
такой же запрос вернёт `200` и ту же задачу. Перезапустить намеренно — `"force": true`.

Параметры по умолчанию — те, на которых Marlin обучался и на которых гонялась гипотеза 0:
`fps: 2.0`, `max_new_tokens: 512`, `prompt_mode: "caption"`.

`prompt_mode` заслуживает пояснения. `caption` — родной режим модели, тот самый
`Describe the video with a scene summary and timestamped events`, разбор через
`from_marlin`. `json` — наш промпт со схемой и разбор через `from_json`. Второй держится
запасным путём: у Marlin `custom_code`, и насколько она держит структуру ответа — вопрос,
который проверяется замером, а не документацией.

### 4. Следить за прогрессом

Опросом:

```bash
curl -s localhost:8000/api/v1/jobs/8f1e…
```

```json
{
  "job_id": "8f1e…", "video_id": "6f2b…", "status": "running",
  "stage": "structure", "stage_index": 3,
  "stages": ["submit","infer","parse","structure","postprocess","keyframes","persist"],
  "progress": 0.72, "eta_s": 9,
  "timings": {"submit": 1.2, "infer": 34.8, "parse": 0.01}
}
```

Или потоком:

```bash
curl -N localhost:8000/api/v1/jobs/8f1e…/events
```

```
event: stage
data: {"stage":"infer","stage_index":1,"progress":0.15}

event: progress
data: {"progress":0.62,"eta_s":21}

event: done
data: {"annotation_id":"c3d9…"}
```

SSE — прогрессивное улучшение. Контракт полностью закрывается опросом; поток лишь убирает
лестницу в индикаторе.

**Честно про `progress`.** Внутри стадии `infer` это **оценка**, а не измерение: Modal
возвращает результат вызова целиком, промежуточного прогресса у нас нет, и число
считается по медиане прошлых прогонов на этом же типе GPU. В интерфейсе его не стоит
подавать как точное — лучше показывать имя стадии, а полосу оставить индикативной.
Остальные стадии считаются по факту.

Бюджет кейса — 2 минуты на ролик, и `timings` существует ровно чтобы этот бюджет мерить,
а не оценивать на глаз.

Передумали — `POST /jobs/{job_id}/cancel`. Задача из очереди снимается сразу; уже уехавшую
на Modal отменить нельзя, вызов досчитается, но результат будет отброшен. Отмена
досчитывающейся задачи всё равно списывает GPU-секунды, и в `cost` они останутся.

### 5. Забрать разметку

```bash
curl -si localhost:8000/api/v1/annotations/c3d9…
```

```
ETag: "1"
```
```json
{
  "annotation_id": "c3d9…", "video_id": "6f2b…", "job_id": "8f1e…",
  "duration_s": 30.0, "fps": 2.0, "model": "marlin-2b+anthropic/claude-haiku-4.5",
  "version": 1,
  "segments": [
    {
      "index": 0, "start_s": 0.0, "end_s": 3.5,
      "action": "берёт", "object": "кружку", "tool": "",
      "confidence": 0.91, "keyframe_ts": 1.8,
      "keyframe_url": "/api/v1/annotations/c3d9…/segments/0/keyframe",
      "edited_by_human": false, "needs_review": false
    },
    {
      "index": 1, "start_s": 3.5, "end_s": 4.0,
      "action": "наливает", "object": "", "tool": "",
      "confidence": 0.41, "keyframe_ts": 3.7,
      "keyframe_url": "/api/v1/annotations/c3d9…/segments/1/keyframe",
      "edited_by_human": false, "needs_review": true
    }
  ],
  "stats": {"segment_count": 7, "edited_count": 0, "needs_review_count": 2,
            "mean_segment_s": 4.28}
}
```

Если `annotation_id` на руках нет, есть вход по ролику:
`GET /videos/{video_id}/annotation` отдаёт самую свежую разметку.

### 6. Править

```bash
curl -s -X PATCH localhost:8000/api/v1/annotations/c3d9…/segments/1 \
  -H 'content-type: application/json' -H 'If-Match: "1"' \
  -d '{"object": "воду", "end_s": 5.2}'
```

Ответ — **вся** разметка с новым `ETag`, а не один сегмент: правка границы может изменить
порядок и, значит, нумерацию соседей.

`edited_by_human` проставляет сервер. Присылать его не нужно, и присланный игнорируется —
иначе флаг перестанет быть замером и станет тем, что клиент про себя сообщил.

### 7. Выгрузить

```bash
curl -sOJ 'localhost:8000/api/v1/annotations/c3d9…/export?format=json'
curl -sOJ 'localhost:8000/api/v1/annotations/c3d9…/export?format=csv'
```

## Экспорт: почему он не равен ответу API

Экспорт отдаёт **канонический формат** — тот же, что описан в
[`annotation.schema.json`](annotation.schema.json) и реализован в `hyp0/schema.py`:

```json
{
  "video_id": "clip00",
  "duration_s": 30.0,
  "segments": [
    {"start_s": 0.0, "end_s": 3.5, "action": "берёт", "object": "кружку",
     "tool": "", "confidence": 0.91, "keyframe_ts": 1.8, "edited_by_human": false}
  ],
  "fps": 2.0,
  "model": "marlin-2b+anthropic/claude-haiku-4.5",
  "meta": {"job_id": "8f1e…", "prompt_mode": "caption"}
}
```

Ни `annotation_id`, ни `version`, ни `index`, ни `needs_review` в выгрузку не попадают.
Причина практическая: `hyp0/metrics.py` уже читает ровно эту форму, и выгрузку из
приложения можно скормить метрике без конвертера. Метрика тогда меряет то, что реально
уехало пользователю, а не промежуточное представление.

Индекса шага в файле нет намеренно — порядок задаёт массив.

### Валидация перед отдачей

Сервер валидирует результат по JSON Schema **до** ответа. Не прошло — отдаётся `500` с
кодом `export_schema_invalid` и списком нарушений в `errors[]`, файла пользователь не
получает. Требование кейса «файлы JSON и CSV проходят проверку формата в 100 % случаев»
держится этой конструкцией, а не аккуратностью: невалидный файл физически не может выйти
наружу.

Пустая разметка отсекается раньше и отдельно — `422` с кодом `annotation_empty`, чтобы
пользователь получил внятное «выгружать нечего», а не отказ валидатора.

Сама схема отдаётся наружу: `GET /schema/annotation.json`. Это та же копия, по которой
валидирует сервер, — чтобы у клиента и у внешних потребителей не завелась своя, которая
однажды разойдётся.

### CSV

Плоская проекция того же, строка на шаг. RFC 4180, UTF-8 **без BOM**, `\n`, точка как
десятичный разделитель, три знака после запятой, заголовок обязателен.

| Колонка | Тип | Заметка |
|---|---|---|
| `video_id` | строка | повторяется в каждой строке |
| `segment_index` | целое | с нуля; в JSON его нет, здесь он нужен, потому что строки в таблице переставляются |
| `start_s` | число | |
| `end_s` | число | |
| `action` | строка | |
| `object` | строка | |
| `tool` | строка | обычно пусто |
| `confidence` | число или пусто | пусто = `null` |
| `keyframe_ts` | число или пусто | |
| `edited_by_human` | `true` / `false` | |

```csv
video_id,segment_index,start_s,end_s,action,object,tool,confidence,keyframe_ts,edited_by_human
clip00,0,0.000,3.500,берёт,кружку,,0.910,1.800,false
clip00,1,3.500,5.200,наливает,воду,,0.410,3.700,true
```

### Round-trip

`POST /annotations/import` принимает выгруженный JSON обратно. Он существует не ради
пользователя, а ради теста: выгрузили → загрузили → сравнили — штатный путь API, а не
отдельный скрипт, который однажды разойдётся с сервером.

## Версии и одновременные правки

`GET` разметки отдаёт `ETag: "N"`, где `N` — `version`. Любая правка требует `If-Match` с
этим значением:

- нет заголовка → `428`-подобный отказ, код `version_missing`;
- версия устарела → `409`, код `version_conflict`.

При конфликте клиент обязан перечитать разметку, а не повторять запрос: `409` означает,
что кто-то (или другая вкладка) уже что-то поменял, и слепой повтор затрёт чужую работу.

Полной истории версий нет — `version` служит только оптимистичной блокировкой. Это
осознанное ограничение скоупа.

## Ошибки

RFC 9457, `application/problem+json`. Ветвиться следует по `code`, а не по тексту:

```json
{
  "type": "about:blank",
  "title": "Границы шагов пересекаются",
  "status": 422,
  "code": "segment_overlap",
  "detail": "Шаг 3 (4.0–7.5 с) заходит на шаг 4 (6.0–9.0 с).",
  "errors": [{"pointer": "/segments/3/end_s", "message": "Должно быть не больше 6.0"}]
}
```

Коды, на которые у интерфейса должна быть отдельная реакция:

| Код | Когда | Что показать |
|---|---|---|
| `video_duration_out_of_range` | ролик короче 5 или длиннее 30 с | назвать фактическую длительность и допустимую |
| `video_resolution_too_low` | высота меньше 720 | то же |
| `model_parse_failed` | Marlin ответил, но разбор не нашёл ни одного шага | предложить сырой ответ (`/jobs/{id}/raw`) и перезапуск |
| `inference_timeout` | вызов Modal не уложился | перезапуск, упомянуть холодный старт |
| `version_conflict` | разметку изменили параллельно | перечитать, показать, что изменилось |
| `segment_overlap` | правка границы налезла на соседа | подсветить обоих соседей |
| `annotation_empty` | выгрузка при нуле шагов | сказать, что выгружать нечего |
| `export_schema_invalid` | наша ошибка, не пользовательская | показать как сбой сервиса, а не как ошибку ввода |

`model_parse_failed` стоит отдельно от `inference_failed` намеренно: провал разбора нельзя
записывать в провал модели. Это правило пришло из `hyp0/parse.py`, где такие ролики
считаются в отдельную графу, и в API оно тоже отдельный код.

## Что чему соответствует в интерфейсе

Таблица нужна, чтобы разбор дизайна и контракт проверяли друг друга: если у элемента
редактора нет эндпоинта — что-то забыли.

| Элемент интерфейса | Вызов |
|---|---|
| Дропзона, её лимиты и подписи | `GET /config`, `POST /videos` |
| Плеер, перемотка | `GET /videos/{id}/content` (с `Range`) |
| Полоса кадров под таймлайном | `GET /videos/{id}/frame?ts=&w=` |
| Индикатор обработки по стадиям | `GET /jobs/{id}` или `GET /jobs/{id}/events` |
| Кнопка «показать ответ модели» при сбое | `GET /jobs/{id}/raw` |
| Таймлайн с сегментами, список шагов | `GET /annotations/{id}` |
| Перетаскивание границы | `PATCH …/segments/{index}` (`start_s` / `end_s`) |
| Правка действия, объекта, инструмента | `PATCH …/segments/{index}` |
| Замена ключевого кадра | `PATCH …/segments/{index}` (`keyframe_ts`) |
| Превью ключевого кадра в карточке шага | `GET …/segments/{index}/keyframe` |
| Добавить шаг | `POST …/segments` |
| Удалить шаг | `DELETE …/segments/{index}` |
| Разрезать шаг | `POST …/segments/{index}/split` |
| Слить с соседним | `POST …/segments/{index}/merge` |
| Подсветка неуверенных шагов | поле `needs_review` в ответе |
| Счётчики в шапке | поле `stats` |
| Автосейв | `PUT /annotations/{id}` с `If-Match` |
| Экспорт | `GET /annotations/{id}/export?format=` |

Про `needs_review` стоит сказать прямо, потому что это единственное место, где дизайн
диктует форму API. Палитра интерфейса монохромная и второй цвет в ней запрещён — значит
уверенность нельзя закодировать красным, жёлтым и зелёным. Клиенту нужен готовый булев
признак, а не порог, который каждый экран определит по-своему. Правило: `confidence` ниже
`confidence_threshold`, либо пустой `action` или `object`, либо шаг короче `min_segment_s`.

`split` и `merge` — тоже не украшение. Пересегментация и недосегментация это две самые
частые ошибки, и в `hyp0` замерено, что равномерное разбиение даёт boundary F1 = 0.59
даром: недосегментация выглядит как приличное число. Значит склейку и разрез надо чинить
одним жестом, а не тремя перетаскиваниями.

## Служебное

`GET /health` — состояние зависимостей: база, живость воркера, доступность Modal-функции и
прогрет ли её контейнер. Поле `ready` отвечает на один вопрос: можно ли сейчас принимать
задачи. При `ready: false` фронту следует не прятать форму загрузки, а сказать, почему
обработка недоступна, — холодная Modal-функция и лежащая база выглядят для пользователя
одинаково, но чинятся по-разному.

`GET /config` — лимиты и опции, см. шаг 1 сценария.

## Чего в API нет

- Аутентификации, ролей, биллинга — вынесено кейсом.
- Истории версий разметки и отката.
- Пакетной обработки: ролики загружаются по одному.
- `POST …/segments/{index}/suggestions` описан, но в первой версии отвечает `501`.
  Контракт зафиксирован заранее, потому что от подсказок зависит обещанное трёхкратное
  сокращение времени: разметчик, не согласный с моделью, должен получать список вариантов,
  а не пустое поле.
