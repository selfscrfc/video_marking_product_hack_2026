# Фронтенд: разметка видео

React + TypeScript + Vite. Экраны собраны по макету «Разметка видео — Hi-Fi»,
данные — по контракту `../spec/openapi.yaml`.

## Запуск

```bash
npm install
npm run seed     # положит два настоящих ролика из ../../hyp0/clips в public/mock
npm run dev      # http://localhost:5173
```

`npm run seed` не обязателен: без него плеер честно показывает заглушку вместо
видео, а кадры не снимаются. С ним всё работает на реальных роликах.

## Мок и настоящий бэкенд

По умолчанию фронт идёт в настоящий бэкенд: `/api/v1` проксируется на
`VITE_API_BASE` (по умолчанию `http://localhost:8000`), см. `vite.config.ts`.
Стек поднимается из корня репозитория:

```bash
docker compose -f ../back/docker-compose.yml up -d
curl -s localhost:8000/api/v1/health     # ready: true
```

Мок (`src/mock/`) включается явно — им удобно открыть UI, когда стек не поднят:

```bash
VITE_USE_MOCK=1 npm run dev
```

Он перехватывает `fetch` и `XMLHttpRequest` и отвечает по тому же контракту, что
описан в спеке: те же коды ошибок, `If-Match` с конфликтом версий, проверка
пересечения границ, пересортировка и переиндексация шагов, пересчёт
`needs_review`.

Это сделано намеренно. Мок, который добрее настоящего сервера, приучает фронт к
поблажкам, и всё ломается в день интеграции.

Разметка в моке — настоящая ручная из `hyp0/gt_merged`, а не выдуманная.
Уверенности проставлены здесь (в эталоне их нет): у одного шага она ниже порога,
чтобы путь «шаг требует проверки» был виден без подгонки данных.

## Проверки

```bash
npm run typecheck
npm run build

# главное: выгрузка проходит настоящую JSON Schema
npx esbuild src/dev/export-check.ts --bundle --format=esm --platform=node \
  --outfile=/tmp/export-check.mjs
node /tmp/export-check.mjs json
```

## Где что

```
src/api/        типы, клиент, форматирование, состояние ролика
src/mock/       мок бэкенда: данные из hyp0 и маршрутизация по контракту
src/components/ плеер, таймлайн, ключевой кадр, панель интервала, загрузка
src/pages/      список видео, обработка, проверка, готовая разметка
src/styles/     токены с макета и один стилевой слой
```

## Чем отличается от макета

Отличия сознательные, каждое — следствие контракта или постановки кейса.

- **Кнопки «Сохранить» на экране проверки нет.** Каждая правка уходит на сервер
  сразу, отдельным `PATCH` с `If-Match`. Кнопка предлагала бы нажать то, что уже
  произошло; вместо неё показывается состояние сохранения и номер версии, а
  внизу редактора — акцентная строка на время, пока правка ещё не на сервере.
- **Ограничения загрузки берутся из `GET /config`**, а не зашиты в подпись. В
  макете написано «до 500 МБ · до 60 секунд», в постановке кейса — 5–30 секунд и
  от 720p. Правда за сервером, иначе подпись однажды разойдётся с проверкой.
- **Действие и объект выбираются из слов, уже встреченных в этом же ролике**, плюс
  свободный ввод. В макете показан список-словарь, но фиксированного словаря у
  продукта нет и быть не может: домен заранее неизвестен, разметка zero-shot.
- **Масштаб дорожки — четыре пресета, а не ползунок**, и заданы они не
  множителем, а тем, сколько секунд ролика видно: «весь ролик», 10, 4, 2 с.
  Множитель сам по себе ничего не говорит, а на ролике 5–30 секунд один и тот
  же ×4 означает совершенно разное. Вариант, который на коротком ролике
  совпадает с «весь ролик», гаснет, но не исчезает — иначе кнопки прыгают при
  переходе между роликами. Шаг рисок подбирается так, чтобы они не сходились
  ближе 26 px, и показан рядом с пресетами.
- **Имени проверяющего нет.** В макете «проверено А. Ивановой», но роли
  пользователей кейс выносит из скоупа. Осталась дата.
- **Рамки объекта на ключевом кадре нет.** В макете она нарисована, но модель
  координат объектов не возвращает — рисовать её значило бы показывать
  возможность, которой нет.
- **Уверенность не кодируется цветом.** Второй цвет в системе один и занят
  тревогой; шаг на проверку помечен штрихом слева, а сколько таких шагов —
  видно в шапке. В блок на дорожке слово не влезает: при десятке интервалов
  блок узкий, там помещается только подпись.
- **Пропуски в покрытии показываются явно.** В макете подпись «пропусков нет»
  статичная; на реальных данных пропуски есть (например, первые две секунды до
  начала действия), и молчать о них нельзя.
- **Добавлена ручка `POST /annotations/{id}/review`.** Макет требует «Завершить
  разметку» и статус «Успешная разметка», а в контракте такого действия не было —
  дыра в спеке, а не в макете. Добавлено и в `../spec/openapi.yaml`.
- **Удаление ролика спрашивает подтверждение.** В макете строка каталога удаляется
  сразу. Но удаление каскадное — вместе с роликом уходит разметка, — а истории
  версий в продукте нет. В диалоге написано, что именно потеряется.
- **Повторно загруженный файл не создаёт вторую строку.** Сервер дедуплицирует по
  содержимому, а не по имени: переименованный файл — тот же ролик. Диалог загрузки
  говорит об этом прямо и называет имя, под которым ролик уже лежит, иначе
  пользователь ищет в списке своё новое имя и не находит.
- **Неполная разметка помечена полосой.** Если стадия `structure` не отработала,
  описание шага остаётся одной строкой, а объект пуст. Это не ошибка действия, поэтому
  полоса не закрывается крестиком: состояние данных никуда не денется.
